# DomSeek

Chrome / EdgeなどのChromium系ブラウザで、ページのリンクやボタンをキーボードから検索して実行するManifest V3拡張機能です。

## 導入

Node.js 22以上で以下を実行します。

```sh
npm ci
npm run build
```

1. Chromeの `chrome://extensions`、またはEdgeの `edge://extensions` を開きます。
2. デベロッパーモードを有効にします。
3. 「パッケージ化されていない拡張機能を読み込む」で、このリポジトリの `dist` フォルダーを選びます。
4. 通常のWebページで **Alt+Shift+K** を押します。拡張機能のツールバーボタンからも起動できます。

ショートカットは `chrome://extensions/shortcuts` または `edge://extensions/shortcuts` から変更できます。競合して起動しない場合もここで確認してください。ソースを変更したら再ビルドし、拡張機能の管理画面で再読み込みします。

## 操作

- 入力すると最大10件の候補を表示します。未入力時は表示しません。
- `↑` / `↓` で選択、`Enter` で実行、`Esc` またはパネル外のクリックで閉じます。
- 候補はマウスでも選択できます。
- 日本語IMEの変換確定中のEnterでは実行しません。
- 検索中は元ページの要素を強調表示したり、候補に合わせてスクロールしたりしません。

## 対象と検索

リンク、ボタン、`summary`、`role="button"` / `role="link"` / メニュー項目、`onclick` 属性のある要素を対象にします。検索には要素のテキスト、アクセシブルな名前（`aria-label` / `aria-labelledby`）、`title`、画像の代替テキストなどを使います。英字の大小と全角半角は正規化します。

検索・順位付けは **Fuse.jsの標準設定**を使い、独自の順位変更やフィールドの重み付けはしません。外部送信や検索履歴の保存は行いません。ライブラリは拡張機能内に同梱します。

画面外の要素に加え、次の閉じた領域も対象にします。

- HTML標準の `<details>` 内に存在する操作要素
- `aria-controls`、または `aria-expanded` / `aria-haspopup` のある開閉ボタンと `aria-labelledby` で対応付けられたパネル内に存在する操作要素

所属先は候補の補助情報に表示します。確定時には、外側から順に折りたたみやメニューを開いて操作を実行します。開けない場合はエラーを表示し、非表示の対象をそのまま実行しません。

## メニューの自動収集

起動時に、`aria-haspopup="menu"` または `aria-haspopup="true"` のあるボタンを最大12個まで順番に開き、生成された項目を収集して閉じます。開くまでHTMLが存在しない項目も、この方法で検索候補に加えます。最初から開いていたメニューは収集後も閉じません。

収集中も検索欄への入力を続けられ、取得した候補を順次反映します。収集した項目を確定すると、メニューを開き直し、名前・役割・リンク先で同じ項目を探して実行します。項目が変更されていた場合はエラーを表示します。候補の情報はパネルを開いている間だけ保持します。

項目抽出はメニュー内だけを走査します。メニュー内のDOM更新が24ミリ秒落ち着いた時点で収集し、`aria-busy="true"`による読み込み表示や、項目がまだ表示されていない場合は最大800ミリ秒まで待ちます。読み込み表示なしで後から追加される項目は、自動収集時に取得できない場合があります。

収集ではメニュー内の操作を実行しませんが、ページ側の開閉処理によって表示の変化や通信が発生することがあります。`Esc`で収集を中止できます。閉鎖できないメニューがあった場合は、それ以降の収集を停止します。

無効な要素、無関係な非表示領域、未使用テンプレートは除外します。同じ操作を表すクリック可能な親子は親を候補にします。別々の操作要素は同じ名前でもまとめず、所属先やリンク先で識別できます。

## 制約

- 自動収集はページ上のメニューボタンが対象です。多段メニューの再帰的な探索、未読み込みの項目、仮想リストの未生成部分には対応していません。起動中に追加された通常の要素は候補に反映します。
- 独自の開閉処理で対応関係を識別できないメニューは、開いてから検索してください。
- openなShadow DOM内は対象です。closedなShadow DOM、iframe内、ブラウザ内部ページや拡張機能の実行が禁止されたページは初版の対象外です。
- `addEventListener` だけで登録され、HTMLの役割や属性から操作要素と分からないものは検出できません。
- 実行はDOMの `click()` を使います。実際のマウス入力と同じイベント列を要求するサイトや、信頼されたイベントのみ受け付ける操作には対応できない場合があります。
- パネルは通常のページ内に表示します。フルスクリーンやブラウザの最前面レイヤー上のダイアログでは、表示・操作に制約があります。

要求権限は `activeTab` と `scripting` です。起動したタブのメインフレームへスクリプトを挿入し、常時全サイトを監視する権限は要求しません。

## 開発・検証

```sh
npm run build
npm test
```

テストはPlaywrightを使います。Windowsでは既存のChromeまたはEdgeを利用し、それ以外では `npx playwright install chromium` でブラウザを用意してください。ブラウザテストではビルド済みスクリプトをページへ挿入し、候補抽出、閉じた領域の実行、IME、フォーカス復帰、動的更新、自動収集と収集中の連続キー入力を確認します。

自動収集の時間は `node scripts/benchmark-menus.mjs` で測定できます。6個のメニューと500個の無関係なボタンを持つページを3回測定し、18項目を取得したことを確認して中央値を出力します。変更前に `--save-baseline` を付けて実行すると、変更後のコードと比較できます。
